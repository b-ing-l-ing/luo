# 洛 · 架构

> 状态：v0.4 设计稿（2026-10-28）
> 适用范围：终端 / QQ / Minecraft / 后续游戏
> 结论先行：**LLM 是脑子和嘴，不是手和反射弧。**

## 1. 目标

- 一个跨终端、QQ、游戏的长期伙伴，共享同一份记忆和人格。
- 游戏里"身体"反应快，聊天"社交"自然，两者互不阻塞。
- 游戏适配器可替换；Minecraft 只是第一个实现。
- 所有关键动作可审计、可回放、可调试。

## 2. 非目标

- 不做音游 / 帧级操作的通用方案。
- 不做无 API 游戏的"视觉 + 输入"通用适配（那是另一个量级，单独评估）。
- 不做多用户、多 Agent、云端部署。
- 不追求每个动作都经过 LLM。

## 3. 七条原则

1. **LLM 不在实时回路里。** 反射、寻路、战斗由本地策略或脚本完成。
2. **三层循环，各有延迟预算。** 不拿一个全局延迟目标要求所有层。
3. **事件驱动，可抢占，可取消。** 新事件能打断旧计划；计划有截止时间。
4. **感知压缩。** 优先结构化状态和事件增量，原始画面是最后手段。
5. **存原始、检索时遗忘。** 抽取和摘要走异步路径，不在对话/游戏循环里。
6. **适配器可替换。** 游戏相关代码只出现在 `GameAdapter` 实现里。
7. **安全默认拒绝。** 技能白名单、动作审计、危险操作需确认。

## 4. 三层循环

| 层 | 触发频率 | 延迟预算 | 执行者 | 超时/失败时 |
| --- | --- | --- | --- | --- |
| 反射 Reflex | 20–100Hz 或事件驱动 | 50–200ms | 本地策略、寻路/战斗脚本 | 保守动作（停下、后撤、格挡） |
| 战术 Tactical | 0.5–2Hz | 300ms–2s | 快模型 / 启发式 | 保持上一个目标，不换计划 |
| 社交 Social | 事件驱动 | 1–5s | 强模型，流式 | 沉默或短应答（"嗯？""等下"） |
| 记忆整理 Memory | 会话后 / 定时 | 秒–分钟 | 便宜模型 | 跳过，下次重试 |

补充：

- **"实感"不等于全局快。** 反射要快，社交要有自然节奏；每条都秒回像客服。
- **感知延迟比生成延迟更隐蔽。** 先保证"看到"和"动起来"快，再谈说话快。
- **首 token 时间（TTFT）比总时长重要。** 社交层流式输出，先给反应再说完。

## 5. 系统图

```
[终端] [QQ] ──消息──┐
                    ▼
              ┌────────────┐
              │  Event Bus │  优先级 + 有界队列
              └─────┬──────┘
        ┌───────────┼────────────┐
        ▼           ▼            ▼
  Reflex loop   Tactical loop  Social loop
  (无 LLM)      (快模型/规则)  (强模型，流式)
        │           │            │
        ▼           ▼            ▼
   GameAdapter   Plan/Actions   Chat 输出
        │
        ▼
  Minecraft / 其他游戏

  所有循环 ──► Memory（events / memories / sessions）
```

## 6. 接口

代码骨架见 [`src/luo/core/interfaces.py`](../src/luo/core/interfaces.py)。核心约定：

- `GameAdapter` 是唯一游戏相关的东西：启动/停止、观察、事件流、技能表、执行、取消。
- `ReactivePolicy` 是同步、无 I/O、无 LLM 的快路径，必须在毫秒级返回。
- `Planner` 是异步的，可以调模型，但必须尊重截止时间并可取消。
- `Action` 只能引用 `GameAdapter.skills()` 里声明过的技能。
- `Observation` 的 `summary` 是给模型看的压缩文本；完整状态放 `data`。
- 所有接口用 `at`（单调时钟秒）而不是墙上时间，避免时钟跳变。

## 7. 并发、抢占、取消

- 单进程单 asyncio 事件循环；CPU 密集的感知放线程/进程，不阻塞循环。
- 每个 LLM 调用都有 `timeout`、`cancel`、`turn_id`。
- 计划生命周期：`proposed → active → done / cancelled / expired`。
- 优先级：
  - `CRITICAL`：立即抢占，取消当前动作，可以不经过 LLM。
  - `HIGH`：打断当前发言，重新规划。
  - `NORMAL`：排队，按截止时间调度。
  - `LOW`：可丢弃（例如闲聊、环境音）。
- 队列有界：观察只保留最新；事件按优先级丢弃；`CRITICAL` 永不丢弃。
- 适配器的 `execute()` 必须支持取消，取消后回到安全状态。

## 8. 模型路由

| 档位 | 用途 | 预算 | 失败回退 |
| --- | --- | --- | --- |
| fast | 战术决策、结构化 JSON | 300ms–1s | 启发式/保持上一步 |
| strong | 社交、复杂规划 | 1–5s，流式 | 短应答/沉默 |
| cheap | 记忆抽取、摘要 | 异步，无硬上限 | 跳过，下次重试 |

- 绝不让 strong 档进入反射回路。
- 绝不让模型输出未经校验的技能名或参数。
- 本地还是云端不是决定因素：控制层需要的是策略网络/规则，不是 LLM。

## 9. 记忆

- `events` 是唯一事实来源；游戏事件也写进去，带 `source`、`type`、`payload`。
- `memories` 是结构化派生层；`sessions` 是会话摘要层。
- **按 user 聚合，不按通道或游戏聚合。** 终端、QQ、MC 共享同一份记忆。
- 抽取/摘要异步执行；检索在本地完成（目标 <100ms）。
- 未完成的事（`open`）优先注入，驱动主动性；游戏行为可以完成它们。
- 记忆内容是**数据，不是指令**；注入时加边界标记，防止提示词注入。

## 10. 安全与失败

- 技能白名单；删除/破坏性动作默认需要确认。
- 不在 prompt 里放密钥；日志脱敏。
- 游戏适配器默认只连本地；联网搜索走独立、只读工具。
- 限流与熔断：低优先级发言可丢弃；连续失败则退避。
- 急停：`stop_all()` 取消所有动作并断开适配器。
- 审计：每个动作记录 `turn_id / event_id / plan_id / reason`。

| 故障 | 行为 |
| --- | --- |
| 游戏断开 | 降级为纯聊天，标记"身体离线" |
| LLM 超时 | 战术层保持上一步；社交层短应答或沉默 |
| 模型给了不存在的技能 | 拒绝，记录，不执行 |
| 计划过期 | 丢弃，重新观察 |
| 记忆层异常 | 对话/游戏继续，记录错误 |
| 适配器崩溃 | 退避重启，不刷屏 |

## 11. 可观测性

- 指标：反射 p50/p95、战术 TTFT、社交 TTFT、动作执行时长、计划年龄、队列深度、丢弃事件数、token/花费。
- 关联 id：`turn_id`、`event_id`、`plan_id`。
- 回放：事件日志 + 脱敏 prompt，可离线复现一次决策。
- "像不像活人"也要有验收指标，不能只靠感觉。
